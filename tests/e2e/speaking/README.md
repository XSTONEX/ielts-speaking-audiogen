# 口语音频库浏览器测试（手机端）

测的是 `templates/speaking.html`（/speaking）和隐藏的合集页 `templates/combined.html`（/combined），重点是 2026-11 的手机改版，外加两处桌面也有的老 bug。

**全部跑在沙盒副本上，数据是 `make_fake_data.py` 编的。** 仓库是公开的，不要换成真实录音和文本。

| 文件 | 作用 |
| --- | --- |
| `make_fake_data.py` | 造数据：18 个话题（四个 Part 都有；Part 2 带题卡，有一个故意没填；「其他」里一篇 3000 多字的长文；一个名字带英文单引号的话题），38 条能真正播放的静音 MP3，三个提前做好的合集。登录凭证写到 `<沙盒>/e2e_token.txt` |
| `sandbox.sh` | `start <沙盒> [端口]` 复制代码 → 造数据 → 后台起服务（断网、API key 全空）；`reseed <沙盒>` 只重灌数据；`stop <沙盒>` 停服务 |
| `phone_e2e.js` | 检查脚本 |

## 检查什么

两个内核各跑一遍：WebKit 390×844 触屏（iPhone Safari）、Chromium 360×780 手机模式（安卓）。

- **音频库**：首屏就能看到话题列表；话题一行两张卡片；「最近使用」是两列小卡片；搜索框和 Part 筛选吸顶；翻下去「新建音频」缩成圆按钮；翻到底最后一行不被它盖住；选了 Part 后标题跟着变、「最近使用」收起；「管理」「合集播放页」收进 ⋯ 菜单；按钮不小于 40 / 44px，字不小于 12px，输入框 16px；卡片里没有嵌套按钮。
- **返回**：⋯ 菜单、新建面板、确认框、完整播放器、全屏阅读页都是返回手势先关掉；从话题页返回音频库停在原来的位置（返回键和「‹ 音频库」都试）；不存在的话题只提示一次。
- **搜索**：命中词高亮、话题名不带「P1 -」、带这一条的问题、右边能直接播；点结果进话题那一条直接展开并滚到顶栏下面；可视高度 470（键盘弹起）时搜索框还在。
- **话题页**：底部「连续播放 + 添加」，翻到底不挡最后一条；点一条就地展开，可以同时展开几条；Part 2 题卡默认三行；超过 600 字的原文用全屏阅读页；⋯ 里全部展开、管理、编辑题卡、合集、删除话题；删除确认从底部升起，写的是问题而不是文件名。
- **播放**：迷你播放条 64px，写这一条的问题和「话题 · 第几条」；完整播放器（倍速四档、上一条 / 下一条、拖进度）；连播自动下一条并展开；提示条浮在播放条上面；**Media Session**（锁屏 / 耳机）的标题、话题、播放状态跟着变。
- **进度条（老 bug，桌面也有）**：拖动时浏览器发 `pointercancel` 以后进度不能冻住（WebKit 用合成的指针事件，Chromium 再用 CDP 真手指拖一次）；桌面宽度也测一遍。
- **新建音频**：几乎全屏的面板，「生成音频」钉在底部；Part 2 题卡排在英文和按钮上面；英文框至少 6 行；话题联想直接排在输入框下面；「生成后留在这个话题」是一整行开关；生成失败（沙盒没有 key，一定失败）显示一句人话 + 「重试」，不显示原始异常，按钮的「＋」不丢；从话题页打开只显示「存入 … · 更改」；可视高度 470 时输入框和「生成音频」、编辑题卡的文本框和「保存」都在屏幕里。
- **读取中 / 空 / 出错**：占位卡片；空库有「新建第一条」；列表加载失败有「重试」；很长的提示条会换行。
- **深色**：排序按钮只露图标；迷你播放条和卡片同色。
- **桌面深色（老 bug）**：1280 宽深色下排序框是本页的暖色底、带下拉箭头；播放条是本页的暖色底，不是 theme.css 给 `#playerBar` 的蓝灰。
- **合集页**：页面请求的合集音频地址能拿到文件（以前是 `.mp3.mp3`，永远 404）；返回按钮回口语音频库，从话题过来回到那个话题；分类一排横滑、每个话题一行两个 44px 按钮；播放器从底部升起、列表不动、返回手势收起；名字带单引号的话题按钮正常。

后端那两处修复（合集音频地址、Part 2 生成失败不留空文件夹）另有单元测试 `tests/test_speaking_routes.py`。

## 跑法

需要 node 22，以及一份 `playwright-core`（本机借用 `my_own_odyssey/frontend/node_modules` 里的那份，浏览器已经装在 `~/Library/Caches/ms-playwright`）。

1. 建沙盒并起服务（沙盒要放在仓库外面）。不要用 5060 / 5061，Chrome 不让打开：

```bash
SB=$(mktemp -d)/sp
tests/e2e/speaking/sandbox.sh start "$SB" 5111
```

2. 跑检查。脚本会让「生成音频」失败一次、切换管理模式，但不删任何东西；**再跑之前先 `sandbox.sh reseed "$SB"`**（服务不用重启）：

```bash
cd tests/e2e/speaking
SP_BASE_URL=http://127.0.0.1:5111 SP_SANDBOX="$SB" SP_SHOTS=/tmp/sp_shots \
PLAYWRIGHT_CORE=/Users/shiqiwen/my_project/my_own_odyssey/frontend/node_modules/playwright-core \
~/.nvm/versions/node/v22.23.1/bin/node phone_e2e.js all
```

- 参数：`webkit`、`chromium` 或 `all`（默认）。
- `SP_SHOTS` 设了就把每个画面的截图存到那里。
- 最后一行是「通过 N 项，失败 M 项」，有失败时退出码是 1。

3. 跑完 `tests/e2e/speaking/sandbox.sh stop "$SB"`。

2026-11-03 的结果：两个内核共 271 项全部通过（WebKit 135、Chromium 136，后者多一项真手指拖进度条）。桌面深色那 4 项对着修之前的 main 跑会失败（播放条 rgb(16, 27, 45)、排序框没有箭头）。

2026-11-01 的结果：两个内核共 265 项全部通过（WebKit 132、Chromium 133）。同一份脚本对着改版前的 `mobile/base` 跑，通过 29 项、失败 72 项（新布局的元素不存在，好几组检查直接跑崩；合集音频 404；拖进度条被取消后时间冻在 0:00）。
